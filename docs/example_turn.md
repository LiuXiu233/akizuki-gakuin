# 一个回合长什么样

下面这个例子里，**所有数字都来自真实的引擎调用**（seed=20250416），
只有叙事文字是 Agent 写的。这就是每回合应该输出的样子。

---

## 玩家输入

```
午休我去食堂，看看凛在不在。如果在就过去跟她聊聊昨天她提过的那个动画。
```

---

## Agent 的工具调用序列

```python
get_world_state()                                   # 12:38，周三，午休，食堂开着
get_nearby_characters()                             # 天野凛在场（core，活动=午休）
get_relationship("player", "npc_amano_rin")         # "认识"，无数值
get_relevant_memories("npc_amano_rin", participants=["player"])
perform_action("talk", target="npc_amano_rin",
               knowledge="anime", minutes=20,
               situational_modifiers={"午休的轻松气氛": 1})
add_memory("npc_amano_rin", fact=..., interpretation=..., emotion=...)
end_turn()                                          # 后台模拟 + 随机事件 + 晋升 + 存档
get_turn_panel(); get_action_context()
record_recommendations([...])
```

## 这个例子里做对了什么

| 做法 | 为什么 |
|---|---|
| 没有写「凛的好感 +2」 | 关系变化用「她说的是'下次'」来表现 |
| 没有替玩家做决定 | 玩家没说要坐下，是天野邀请的；玩家的下一步留给玩家 |
| 判定只影响表达效果 | 成功 = 话题聊起来了，不是「她因此喜欢你」 |
| 数字全部来自引擎 | D20、修正、XP、时间、精力都是 `perform_action` 返回的 |
| 推荐行动贴合现实状态 | 预备铃响了，所以推荐都是 5～20 分钟的事，没有「约她出去」 |
| 有群像感 | 第 4 条推荐把镜头分给了另一个正在过自己生活的人 |

## 反面教材

```
✗ 【剧情】
✗ 你开心地坐了下来，心跳加快。          → 替玩家做决定和产生情绪
✗ 【天野凛好感度 +3】                   → 泄露隐藏数值
✗ 她的好感度已经很高了，现在告白成功率很大  → 泄露 + 暗示成功率
✗ （Natural 20）她被你说服了，答应做你女朋友 → 骰子剥夺 NPC 自主权
✗ 你想了想，决定去图书馆。               → 替玩家行动
```
